# Versioning

Bump `CFBundleVersion` and `CFBundleShortVersionString` predictably — across Xcode, project specs, and App Store Connect.

## Overview

iOS uses Apple's two-version model:

| Plist key | Format | Role |
|---|---|---|
| `CFBundleShortVersionString` | `MAJOR.MINOR.PATCH` | User-facing **marketing** version. Bump manually for releases. |
| `CFBundleVersion` | plain integer (or `MAJOR.MINOR.PATCH.BUILD`) | Internal **build counter**. Auto-incremented on every beta. |

Android uses `versionName` (marketing) and `versionCode` (monotonic integer) — same shape, different field names.

``VersionAction`` and ``VersionBumper`` keep all four values consistent regardless of where the source of truth lives.

## Bump types

| `bump` | Effect on marketing | Effect on build counter |
|---|---|---|
| `build` | unchanged | +1 |
| `patch` | `1.2.3` → `1.2.4`, build resets to 1 | reset to 1 |
| `minor` | `1.2.3` → `1.3.0`, build resets to 1 | reset to 1 |
| `major` | `1.2.3` → `2.0.0`, build resets to 1 | reset to 1 |

For a beta lane that just needs a unique TestFlight build:

```yaml
workflows:
  beta:
    - action: version
      options: { bump: build }
    - action: archive
    - action: testflight
```

## Sources of truth

The `versioning.source` Shipfile key tells ShipItKit **where to read and write** version values:

| Source | Read from | Write to | When to use |
|---|---|---|---|
| `xcodeproj` (default) | `.xcodeproj` build settings via `agvtool` | same | Standard Xcode projects |
| `project_spec` | `Project.yml` (XcodeGen) or `Project.swift` (Tuist) | same YAML/Swift | Generated projects, where `.xcodeproj` is rebuilt every run |
| `asc` | App Store Connect API | `.xcodeproj` (writes back the next build number ASC expects) | Centralised, multi-machine teams |

```yaml
versioning:
  strategy: sequential   # or: timestamp, commitCount
  source: xcodeproj      # or: project_spec, asc
```

## Build number strategies

``BuildNumberStrategy`` controls *how* the next build counter is computed:

| Strategy | Output | Notes |
|---|---|---|
| `sequential` | current + 1 | Default. Plain integer. |
| `timestamp` | `YYYYMMddHHmm` | Useful when teams race uploads. |
| `commitCount` | total commits on current branch | Reproducible from git. |

```yaml
versioning:
  strategy: timestamp
```

## Project-spec versioning

If your `.xcodeproj` is generated by XcodeGen or Tuist, the `xcodeproj` source loses round-trips: `agvtool` writes to a project that gets regenerated on the next build. Use `project_spec` instead — it reads/writes the spec file directly.

```yaml
versioning:
  source: project_spec    # Reads Project.yml or Project.swift
```

The `project_spec` source handles both XcodeGen YAML and Tuist Swift specs — it edits the spec in place so subsequent regenerations preserve the bump.

## Programmatic use

```swift
let result = try await VersionAction().run(
    with: .init(bump: .build),
    context: context
)
print("New marketing version: \(result.marketingVersion)")
print("New build number:      \(result.buildNumber)")
```

Or directly via ``VersionBumper`` if you don't want to go through the action:

```swift
let bumper = VersionBumper(context: context)
let bump = try await bumper.bump(options: .init(bump: .patch))
```

## Android versioning

For Android, ``VersionAction`` updates `versionCode` (monotonic) and `versionName` (semver) in `app/build.gradle` (or `.kts`).

```yaml
platform: android

workflows:
  beta:
    - action: version
      options: { bump: build }
    - action: archive
    - action: play-store
```

Google Play rejects an upload whose `versionCode` is not strictly greater than every prior upload — `bump: build` enforces that automatically.

## Common pitfalls

| Symptom | Cause | Fix |
|---|---|---|
| Build number resets every run | Project regenerated by XcodeGen/Tuist | Switch `versioning.source` to `project_spec` |
| ASC rejects build: "version already exists" | Two CI machines using `sequential` strategy | Switch to `timestamp` or `asc` |
| Marketing version unchanged after `bump: minor` | Manual override in Info.plist | Remove the override, let `agvtool` manage it |
