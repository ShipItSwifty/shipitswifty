# Flutter and React Native integration

Ship Flutter and React Native apps to the App Store and Google Play from a single Shipfile.

## Overview

ShipItKit provides first-class runtime support for Flutter and React Native projects through the ``BuildSystem`` axis. Like ``BuildSystem/kmp``, setting `build_system: flutter` or `build_system: react_native` in your Shipfile activates framework-aware builds, tests, and lint runs — no custom scripts required.

| Framework | iOS action | Android action |
|---|---|---|
| Flutter build | `flutter build ipa` | `flutter build apk` |
| Flutter archive | `flutter build ipa` | `flutter build appbundle` |
| React Native (build) | `npx react-native build-ios` | `npx react-native build-android` |
| React Native (archive) | `xcodebuild archive` + export | `npx react-native build-android --tasks bundleRelease` |
| Test | `flutter test` | `flutter test` |
| Test (RN) | package manager `test` script | package manager `test` script |
| Lint | `flutter analyze` | `flutter analyze` |
| Lint (RN) | package manager `lint` script | package manager `lint` script |

### Flutter iOS: no separate export step

`flutter build ipa` produces the IPA directly at `build/ios/ipa/*.ipa`. Unlike native iOS,
there is **no** separate `export` step. The generated workflow omits `ExportAction`:

```yaml
workflows:
  beta:
    - action: test
    - action: archive          # runs: flutter build ipa
    # - action: export         # NOT needed for Flutter iOS
    - action: testflight
```

### React Native iOS: hybrid pipeline

The RN CLI does not produce an App Store-grade archive. `ArchiveAction` uses `xcodebuild archive`
on the Xcode project generated by `npx react-native init` (or Expo). `ExportAction` and
`TestFlightAction` then proceed exactly as they would for a native iOS app.

```yaml
workflows:
  beta:
    - action: lint
    - action: test
    - action: archive          # runs: xcodebuild archive on the RN-generated project
    - action: export
    - action: testflight
```

### React Native test and lint use package manager scripts

ShipItKit auto-detects the JS package manager from lockfiles:

| Lockfile | Manager |
|---|---|
| `pnpm-lock.yaml` | pnpm |
| `yarn.lock` | yarn |
| `package-lock.json` / fallback | npm |

The `test` and `lint` actions run `<pm> run test` / `<pm> run lint`. When the `test`
script supports Jest CLI passthrough, ShipIt also collects Jest JSON via `--json --outputFile`
so `TestRunReport` can include named failures and rerun selectors. If the script is absent
from `package.json`, the action throws ``ShipItError/invalidConfiguration(reason:)`` with a
clear message rather than silently invoking the package manager.

## Auto-detection

`ConfigResolver` activates the build system automatically when `build_system` is omitted:

| Marker file | Detected value |
|---|---|
| `pubspec.yaml` containing `flutter:` | `.flutter` |
| `package.json` containing `react-native` | `.reactNative` |

You can also set it explicitly to opt in regardless of project structure:

```yaml
ios:
  build_system: flutter
android:
  build_system: flutter
```

or for React Native:

```yaml
ios:
  build_system: react_native
android:
  build_system: react_native
```

## Minimal Shipfile — Flutter

```yaml
# Shipfile.yml
ios:
  build_system: flutter
android:
  build_system: flutter

workflows:
  beta-ios:
    - action: test
    - action: archive
      options: { platform: ios }
    - action: testflight

  beta-android:
    - action: test
    - action: archive
      options: { platform: android }
    - action: play-store
```

## Minimal Shipfile — React Native (iOS)

```yaml
# Shipfile.yml
app:
  scheme: ${SHIPIT_APP__SCHEME}
  bundle_id: ${SHIPIT_APP__BUNDLE_ID}
  team_id: ${SHIPIT_APP__TEAM_ID}

ios:
  build_system: react_native

code_signing:
  type: automatic

workflows:
  beta:
    - action: lint
    - action: test
    - action: archive
    - action: export
    - action: testflight
```

## Minimal Shipfile — React Native (Android)

```yaml
# Shipfile.yml
android:
  build_system: react_native
  package_name: ${SHIPIT_ANDROID__PACKAGE_NAME}

workflows:
  beta:
    - action: lint
    - action: test
    - action: archive
    - action: play-store
      options:
        track: qa
```

## CLI usage

```sh
# Detect build system and generate a Shipfile
shipit inspect --output json
shipit generate --goal beta

# Check toolchain
shipit doctor

# Lint / test / archive
shipit lint --platform ios
shipit test --platform ios
shipit archive --platform ios           # Flutter: flutter build ipa
shipit build --platform android         # Flutter: flutter build apk
shipit archive --platform android       # Flutter: flutter build appbundle

# Full workflow
shipit run beta --ci --output json

# Validate the Android artifact
shipit validate bundle

# Upload to Google Play (AAB path auto-discovered for Flutter/RN)
shipit play-store --track internal
```

## Swift scripting (library mode)

```swift
import ShipItKit

// Flutter iOS
let config = try await ConfigResolver().resolve(
    cliOptions: CLIOptions(platform: .ios),
    shipfilePath: "./Shipfile.yml"
)

let context = ActionContext(
    shell: ShellContext(),
    logger: Logger.forType(subsystem: "ReleaseScripts", ActionContext.self),
    config: config,
    appStoreConnect: AppStoreConnectClient(
        keyID: config.ascKeyID ?? "",
        issuerID: config.ascIssuerID ?? "",
        privateKeyData: config.ascPrivateKeyData ?? Data()
    ),
    platform: .ios
)

_ = try await TestAction().run(with: .init(), context: context)
let archive = try await ArchiveAction().run(with: .init(), context: context)
// archive.ipaPath contains "build/ios/ipa" — IPA ready for upload

// Flutter Android
let androidConfig = ResolvedConfig(
    platform: .android,
    androidBuildSystem: .flutter,
    projectRoot: "."
)
let androidContext = ActionContext(
    shell: ShellContext(),
    logger: Logger.forType(subsystem: "ReleaseScripts", ActionContext.self),
    config: androidConfig,
    platform: .android
)

let androidBuild = try await BuildAction().run(with: .init(), context: androidContext)
// androidBuild.apkPath == "build/app/outputs/flutter-apk/app-release.apk"

let androidArchive = try await ArchiveAction().run(with: .init(), context: androidContext)
// androidArchive.aabPath == "build/app/outputs/bundle/release/app-release.aab"
```

## Artifact paths

| Platform | Build system | Action | Artifact path |
|---|---|---|---|
| iOS | Flutter | `archive` | `build/ios/ipa` (IPA directory) |
| Android | Flutter | `archive` | `build/app/outputs/bundle/release/app-release.aab` |
| Android | Flutter | `build` | `build/app/outputs/flutter-apk/app-release.apk` |
| iOS | React Native | `archive` | `./build/<scheme>.xcarchive` |
| Android | React Native | `archive` | `android/app/build/outputs/bundle/release/app-release.aab` |
| Android | React Native | `build` | `android/app/build/outputs/apk/release/app-release.apk` |

For Flutter flavors, ShipItKit derives the bundle path from `flavor + variant`, such as `build/app/outputs/bundle/freeRelease/app-free-release.aab`.

## CI requirements

| Framework | macOS runner | Java | Node | Flutter SDK |
|---|---|---|---|---|
| Flutter iOS | required | — | — | required |
| Flutter Android | not required | — | — | required |
| React Native iOS | required | — | required | — |
| React Native Android | not required | — | required | — |

The `shipit doctor` command is platform-scoped. For iOS projects it checks the full Xcode toolchain (`xcode-select`, `xcodebuild`, `security`, `xcrun simctl`) plus App Store Connect credentials and network reachability. For Android projects those iOS-specific checks are skipped entirely. On top of that, `doctor` probes for `flutter` and `node` on PATH when the resolved build system is `.flutter` or `.reactNative`.
